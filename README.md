# STM32F103C8T6 Modbus RTU 从机

基于 STM32F103C8T6 + RS485 的 Modbus RTU **从机（Slave）**实现，模拟一个温湿度传感器。

主机用标准 Modbus 功能码即可读写本机的寄存器区；读回的温湿度编码与原传感器一致，
因此本仓库历史提交 `3c93c22`（主机版本）里的代码**一行不用改**就能与本从机对接。

---

## 功能特性

- 从机地址 `0x01`，由 `MODBUS_SLAVE_ADDR` 编译期指定
- 支持功能码 **0x03 / 0x04**（读寄存器）、**0x06**（写单个寄存器）、**0x10**（写多个寄存器）
- 支持广播地址 `0x00`：执行写操作但**不应答**
- 64 个寄存器（地址 `0x0000`~`0x003F`），整片可读可写
- CRC-16/MODBUS 校验；地址不匹配、CRC 错误、帧长非法时**静默丢弃**，不占用总线
- 标准异常应答，异常码 `0x01` / `0x02` / `0x03`
- 0.96 寸 OLED 实时显示从机地址与寄存器中的温湿度

## 硬件连接

| 功能 | 引脚 | 配置 |
|---|---|---|
| USART1 TX | PA9 | 复用推挽输出 |
| USART1 RX | PA10 | 上拉输入 |
| RS485 方向控制 | PB14、PB15 | 推挽输出，高电平发送、低电平接收（两脚同时动作） |
| OLED SCL | PB8 | 推挽输出（软件 I2C） |
| OLED SDA | PB9 | 推挽输出（软件 I2C） |

**串口参数：** 9600 bps，8 数据位，无校验，1 停止位（8N1），无硬件流控。

**接线要点：** 与主机对接时 A/B 不能接反，且两块板必须共地。
接反的典型现象是**完全收不到数据**（RX 无任何反应）。

## 寄存器映射

| 地址 | 名称 | 初值 | 说明 |
|---|---|---|---|
| `0x0000` | 温度 | 253 | 单位 0.1℃，253 表示 25.3℃ |
| `0x0001` | 湿度 | 605 | 单位 0.1%RH，605 表示 60.5%RH |
| `0x0002`~`0x003F` | 保留 | 0 | 预留给后续扩展 |

全部为**可读可写**（0x03 与 0x04 共用同一片寄存器区）。上电后数值不会自动变化，
主机写进来多少、读回去就是多少——联调时"数变了"只可能来自主机写入，排障时少一个变量。

### 温度编码

沿用原传感器的约定，以兼容主机侧原有的解码逻辑：

- 非负温度直接存数值：25.3℃ → `253`
- 负温度存 `10000 + |T|`：-5.3℃ → `10053`

主机侧 `jiema.c` 里的 `if (Tem1 < 10000) Tem = Tem1; else Tem = -(Tem1 - 10000);` 正是按此约定写的。

## 支持的 Modbus 功能码

> 以下示例中 CRC 均为**低字节在前、高字节在后**，已按本工程的 `Modbus_CRC16()` 算好，可直接用串口助手发送。

### 0x03 / 0x04 —— 读寄存器

请求 8 字节，应答 `5 + 2N` 字节，数量合法范围 **1~125**。

```
请求：01 04 00 00 00 02 71 CB          读从机1，起始 0x0000，读 2 个寄存器
应答：01 04 04 00 FD 02 5D AA ED       [01][04][字节数=4][温度=0x00FD][湿度=0x025D][CRC]
```

`0x03` 与 `0x04` 访问同一片寄存器区，用哪个都能读通。

### 0x06 —— 写单个寄存器

请求 8 字节，**应答与请求完全相同**（原帧回显）。

```
请求：01 06 00 00 01 2C 89 87          把温度写成 0x012C = 300，即 30.0℃
应答：01 06 00 00 01 2C 89 87
```

### 0x10 —— 写多个寄存器

请求 `9 + 2N` 字节，应答**固定 8 字节、不含数据**（四个功能码里最容易写错的一个）。
数量合法范围 **1~123**。

```
请求：01 10 00 00 00 02 04 01 2C 02 5D F3 03   写 2 个：温度=0x012C，湿度=0x025D
应答：01 10 00 00 00 02 41 C8
```

### 异常应答

格式：`[从机地址][功能码 | 0x80][异常码][CRCLo][CRCHi]`，共 5 字节。

| 异常码 | 含义 | 触发条件 |
|---|---|---|
| `0x01` | 非法功能码 | 功能码不是 0x03 / 0x04 / 0x06 / 0x10 |
| `0x02` | 非法数据地址 | 起始地址 + 数量越过 `0x0000`~`0x003F` |
| `0x03` | 非法数据值 | 数量为 0 / 超范围；0x10 的字节数与数量不匹配 |

```
发送：01 05 00 00 00 01 <CRC>    （0x05 是线圈写单个，本从机不支持）
应答：01 85 01 83 50
```

异常帧**只**在"地址匹配 + CRC 正确，但功能码或数据非法"时才发出。地址不匹配或 CRC 错误时
必须静默丢弃：总线上可能还有别的从机正在应答，本机再发一帧就会撞车；CRC 错误说明帧本身就是
坏的（噪声或半个帧），应答只会让总线更乱。

## 快速验证

1. **读测试** —— USB 转 485 模块接从机板，用 Modbus Poll 或串口助手发送
   `01 04 00 00 00 02 71 CB`，应收到 `01 04 04 00 FD 02 5D AA ED`
2. **写测试** —— 发送 `01 06 00 00 01 2C 89 87`（温度改为 30.0℃），应答应原帧回显；
   再发读取指令应读回 `0x012C`，OLED 同步显示 `30.0`
3. **异常测试** —— 发送功能码为 `0x05` 的帧，应收到 `01 85 01 83 50`
4. **双机测试** —— 另一块板子烧主机版本代码（提交 `3c93c22`），两块对接，
   主机 OLED 应稳定显示本从机寄存器里的温湿度

## 关键实现说明

### 帧尾判定（Modbus RTU 的 T3.5）

RTU 模式没有帧头帧尾字节，靠总线上 **3.5 个字符时间的静默**划分帧边界。
本工程用"串口中断逐字节收 + TIM2 每 1ms 递减计时"实现：每收到一个字节 `Count` 清零，
连续 `MODBUS_T35_MS` 毫秒无新字节即认为一帧结束，随后置 `RxFlag` 并锁存帧长 `RxLen`。

9600 波特率下 1 字符 = 10 位 ≈ 1.04ms，3.5 字符 ≈ 3.65ms，故取 **4ms**。

> ⚠️ 若把波特率改成 115200，T3.5 只有约 0.3ms，`MODBUS_T35_MS` 必须同步改小，
> 否则从机要等 4ms 才应答，主机会先超时，表现为"从机不响应"。

### 解析在主循环，不在中断里

中断只负责收字节和判帧尾，协议解析与应答在主循环完成。
0x10 的应答在 9600 下要发十几毫秒，若在中断里同步发送会阻塞所有同级及更低优先级中断。

### RS485 收发切换必须等 TC，不能等 TXE

```c
ModeO();                                                      // DE=1，驱动器使能
Serial_SendArray(Modbus_TxBuf, len + 2);
while (USART_GetFlagStatus(USART1, USART_FLAG_TC) == RESET);  // 等最后一位移完
ModeI();                                                      // DE=0，回到接收
```

`TXE` 只表示发送数据寄存器已空，最后一个字节还停在移位寄存器里往外发，此时拉低 DE 会把它截断，
主机侧表现为"偶尔最后一字节丢失、老是报 CRC 错"。

### 收发切换后清理接收状态

切回接收后会调用 `Serial_ClearRx()`（读 SR 再读 DR，一次清掉 RXNE/ORE/NE/FE/PE 并复位接收索引）。
485 方向切换瞬间总线上常有毛刺，不清的话下一次接收可能立刻误触发 RXNE，把噪声当成帧头。

### 接收缓冲区 256 字节

主机版的 9 字节缓冲是按"应答帧正好 9 字节"定的；从机要收 0x10 写请求，最长可达 255 字节，
故按 `MODBUS_BUF_SIZE = 256` 分配。索引 `RNum` 必须是 16 位，8 位存不下"已收满 256 字节"这个状态。

## 已知限制

1. **接收缓冲区存在竞争。** `RxLen` 与 `Serial_RxData` 由中断写、主循环读。主循环拿到帧到处理完
   约 1ms，此间若新帧到达会覆盖缓冲区。正常 Modbus 主机发完请求会等应答，不会出现；
   但若主机超时重发，理论上可能覆盖。本期未处理，仅记录。
2. **从机地址是编译期常量。** 修改地址需改 `Modbus.h` 里的 `MODBUS_SLAVE_ADDR` 并重新编译，
   不支持主机在线改地址。
3. **0x03 与 0x04 共用寄存器区**，不符合"输入寄存器只读"的严格语义，对演练用途可以接受。
4. **不支持线圈 / 离散量（0x01 / 0x05 / 0x0F）**，也不支持 ASCII 传输模式。
5. **波特率不可在线修改**，改变波特率需同时调整 `MODBUS_T35_MS`（见上文）。
